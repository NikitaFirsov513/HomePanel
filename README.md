# Home Panel

Панель управления умным домом на ESP32-P4: Яндекс и Home Assistant,
общий список устройств, редактор плана и интерактивный вид дома.

## Оборудование и окружение

- ESP-IDF 5.5.x или 6.1. Для ESP-IDF 6 cJSON, USB Host
  (зависимость Waveshare BSP) и PHY IP101 подключаются через Component Manager.
- Waveshare ESP32-P4, дисплей 1024×600 (7 inch C), RGB565, PSRAM.
- Один встроенный Ethernet-порт с PHY IP101, DHCP.
- MDC GPIO31, MDIO GPIO52, PHY reset GPIO51, адрес PHY 1.

Для другой платы проверьте настройки Ethernet и Waveshare BSP в menuconfig.
Остальные семейства ESP32 этой конфигурацией не проверены.
В ESP-IDF 6.1 проверьте также ревизию чипа: для ESP32-P4 до v3 включите
CONFIG_ESP32P4_SELECTS_REV_LESS_V3 в настройках Hardware Settings / Chip revision.
В настройках по умолчанию выбраны ранние чипы v0.1–v1.99, включая v1.
Частоты: CPU 360 МГц, Flash 80 МГц, PSRAM 200 МГц.
Логи загрузчика ограничены уровнем WARN, чтобы он помещался до таблицы разделов
по адресу 0x8000. Адреса существующих разделов и уровень логов приложения сохранены.

## Настройка и запуск

В терминале ESP-IDF, из корня проекта:

```powershell
idf.py set-target esp32p4
idf.py menuconfig
```

В разделе **Home Panel** задайте **Yandex OAuth Client ID** и **Yandex OAuth
Client secret (local build only)** своего OAuth-приложения.
В правах приложения должны быть `iot:view` и `iot:control`.
Client ID по умолчанию уже задан для этой панели; секрет хранится только
в локальном `sdkconfig`. Пользовательский access_token в menuconfig больше не нужен.
Здесь же настраиваются период обновления (по умолчанию 60 секунд)
и пауза после ошибки (10 секунд).

Секрет приложения включается в прошивку: защищайте `sdkconfig`, сборочные файлы
и образ прошивки. Не записывайте секрет в исходники или `sdkconfig.defaults`.

```powershell
idf.py build
idf.py -p COM_PORT flash monitor
```

Замените COM_PORT на порт вашей платы. Выход из monitor: Ctrl+].
При смене цели команда set-target сбрасывает текущий sdkconfig; задавайте секрет после неё.
После перехода с ESP-IDF 5.x на 6.1 выполните idf.py fullclean перед сборкой,
чтобы не использовать CMake-кэш и объектные файлы прежнего SDK.

## Вход по QR

1. Подключите Ethernet. Откройте **Подключения → Открыть аккаунт** в карточке Яндекса.
2. Нажмите **Войти по QR**, отсканируйте код камерой телефона.
3. На странице Яндекса (`ya.ru/device` или `oauth.yandex.ru/device`) введите показанный панелью временный код
   и разрешите доступ к умному дому. Панель получит токены автоматически.
4. Закройте раздел аккаунта. Состояния устройств загрузятся без перезагрузки.

Используется [Device Authorization Flow Яндекса](https://yandex.ru/dev/id/doc/ru/codes/screen-code-oauth):
`POST /device/code`, затем `POST /token` с `grant_type=device_code`.
QR содержит только официальный адрес страницы входа, без токенов и секрета.
Короткий пользовательский код вводится на телефоне; скрытый device_code
остаётся на панели. Redirect URI из настроек веб-приложения в этом сценарии не используется.
Если Яндекс отклоняет выдачу кода, проверьте настройки, доступность приложения
и права `iot:view` / `iot:control` в его кабинете.

Для цепочки TLS Яндекса в ESP-IDF 6.1 включена
`CONFIG_MBEDTLS_CERTIFICATE_BUNDLE_CROSS_SIGNED_VERIFY`: сервер передаёт GlobalSign
R3, подписанный старым корнем R1, а актуальный Mozilla bundle уже содержит
самоподписанный R3. Штатная [проверка перекрёстных цепочек ESP-IDF](https://docs.espressif.com/projects/esp-idf/en/latest/esp32p4/api-reference/protocols/esp_crt_bundle.html#cross-signed-certificate-support)
выбирает доверенный R3 из bundle. Проверка подписи и имени сервера включена;
устаревший список корней не добавляется. Локальный `sdkconfig` тоже обновлён.
При другом старом sdkconfig включите эту опцию вручную: defaults не заменяет
сохранённые значения. Ошибка HTTPS на экране теперь содержит код ESP и HTTP-статус.

Панель соблюдает интервал опроса сервера, обрабатывает ожидание, отказ, замедление,
ошибки сети и истечение кода. Устаревший код удаляется; новый выдаётся кнопкой входа.
**Отменить вход** прекращает ожидание. Переключение раздела через верхнюю
навигацию сохраняет ожидание подтверждения; к QR можно вернуться через **Подключения → Открыть аккаунт**.
Для повторного входа после отзыва доступа перепрошивка не нужна.
Если вход уже восстановился автоматически, откройте аккаунт Яндекса и нажмите **Войти заново**.
Панель удалит сохранённую сессию и выдаст новый QR для проверки входа с нуля.
Client ID и Client secret при этом остаются: это ключи OAuth-приложения,
а пользовательские access/refresh-токены хранятся отдельно в NVS.

Пара access/refresh сохраняется одним документом в отдельном NVS-разделе
`auth_nvs` (0x410000, 64 KiB). Адреса `nvs`, `phy_init` и `factory` не меняются;
план дома остаётся в прежнем NVS. При первом обновлении прошивайте обычной командой
`idf.py flash`, включающей новую таблицу разделов, а не только файл приложения.
`erase-flash` не нужен. После перезагрузки сохранённая сессия обновляется через
[refresh_token](https://yandex.ru/dev/id/doc/ru/tokens/refresh-client).
HTTP 401 вызывает обновление токена и однократный повтор GET; команды устройствам
автоматически не повторяются. Токены не передаются в UI или журнал.

**Выйти** удаляет локальные токены и список устройств Яндекса, сохраняя план дома и устройства Home Assistant,
и пытается отозвать токен устройства у Яндекса. Локальный выход работает без сети;
при отсутствии связи удалённый отзыв не гарантируется. При необходимости доступ
можно отозвать в Яндекс ID. NVS без включённого шифрования flash не зашифрован;
защита от чтения памяти устройства в этой конфигурации не включена.

## Home Assistant и общие подключения

Откройте **Подключения → Home Assistant → Настроить**. Укажите адрес сервера,
например `http://192.168.31.10:8123`, и долгосрочный токен доступа из профиля
пользователя Home Assistant (раздел безопасности). Сервер Home Assistant должен
уже работать в вашей сети: на самой ESP32 он не запускается.

Адрес задаётся без `/api`, логина, пароля и параметров. Поддерживаются HTTP
и HTTPS с проверкой сертификата штатным bundle ESP-IDF; самоподписанный
сертификат без доверенного корня не принимается. При HTTP токен передаётся
по локальной сети без TLS. Автоматические перенаправления отключены.

Нажмите **Подключить**. Настройки сохраняются в отдельном пространстве имён
`homeassistant` раздела `auth_nvs` и восстанавливаются после перезагрузки.
Поле токена маскируется и очищается после отправки; сохранённый токен не
возвращается в UI. При редактировании адреса без его изменения можно оставить
поле токена пустым. При смене адреса токен нужно ввести заново.
**Отключить** удаляет только настройки и устройства Home Assistant.

Реализованы следующие сущности HA, в пределах сообщаемых ими возможностей:

- `light`: питание, яркость, RGB-цвет и температура белого света;
- `switch`, `input_boolean`: включение и выключение;
- `vacuum`: старт, пауза, остановка, база и выбор мощности;
- `cover`: открытие, закрытие, остановка и положение;
- `climate`: целевая температура, режим климата и вентилятора;
- `sensor`, `binary_sensor`: показания и события;
- `scene`, `script`, `button`, `input_button`: запуск и нажатие.

Используются [REST API Home Assistant](https://developers.home-assistant.io/docs/api/rest/):
`GET /api/states` раз в 5 секунд и `POST /api/services/<domain>/<service>`
для управления. После команды состояния обновляются повторно. Повторы
команд при тайм-ауте не выполняются. Сообщение об успехе означает принятие
команды сервером; фактическое состояние приходит при обновлении.
WebSocket, MQTT и прямое подключение Zigbee/Matter в эту версию не входят.

Устройства обоих источников доступны в списке и конструкторе дома.
Источник виден в карточке. Привязки Яндекса на ранее сохранённом плане
совместимы; для HA используются отдельные ID с префиксом `ha:`.
При отключении одного источника другой продолжает работать.
Одинаковое физическое устройство из двух систем пока отображается двумя
записями: автоматического объединения по имени нет.
Области HA не импортируются через `/api/states`; размещение по комнатам
задаётся в конструкторе панели. Карты пылесоса, камеры и медиаплееры HA
в этой версии не поддерживаются. Ограничения списка HA: 512 поддерживаемых
сущностей, ответ до 512 KiB и `entity_id` до 124 ASCII-символов.
При ошибке HA его живой список скрывается до восстановления связи,
а сохранённые привязки остаются на плане.

## Поведение

Главный экран после включения — объёмный вид сохранённого дома. Он доступен
сразу, до подключения к сети. Постоянная верхняя навигация **Дом / Устройства /
План / Подключения** доступна во всех разделах. Текущий раздел выделен цветом;
**План** открывает 2D-конструктор, **Устройства** — карточки, **Дом** — проекцию.
Справа виден счётчик активных систем. Нажатие открывает **Подключения**,
где отдельно показаны вход в Яндекс и состояние соединения Home Assistant.
Обновления и результаты команд сохраняют выбранный раздел. Панель управления
устройством открывается поверх текущего раздела и закрывается обратно в него.

После входа и получения IP панель выполняет GET /v1.0/user/info и обновляет состояния
устройств на плане и в списке. Список показывает карточки
с названиями, комнатами и доступными показаниями датчиков.
Карточки расположены в две колонки; шесть устройств помещаются на экране 1024×600.
Иконки различают лампы, пылесосы, колонки и розетки. На карточке видны комната,
состояние и быстрая кнопка питания. Нажмите на карточку, чтобы открыть боковую
панель с полными настройками. Закрытие — кнопкой «Готово» или касанием затемнения.
Пустой список отображается как «Устройств пока нет».
При каждом обновлении экран получает согласованный снимок списка.
Ошибка JSON не уничтожает последний корректный список в памяти.

Пользовательский вход и сохранённый план независимы. После выхода, начала
повторного входа или отзыва доступа облачные карточки и значки в доме удаляются
из отображения сразу; входящие старые снимки без авторизации игнорируются.
Открытый выбор устройств закрывается, незавершённое добавление отменяется.
Добавлять устройства можно после подключения источника и загрузки его текущего списка.
Сохранённые привязки остаются в 2D-плане серыми с пометкой **Нет входа** или
**Недоступно**; боковая панель поясняет **Проверьте подключения** либо
**Нет в текущих подключениях**. Такие привязки можно убрать с плана, они не являются
доступными устройствами. После входа отображаются только ID из текущего аккаунта.

Если сеть недоступна, запрос завершился ошибкой или токен не принят,
экран показывает причину. После восстановления сети запросы возобновляются.
Если вход Яндекса не выполнен или отозван, откройте его аккаунт через **Подключения** и войдите по QR.
Причина ошибки показывается красным текстом. Главный экран и конструктор
доступны даже без Ethernet и без успешной загрузки списка устройств.
Главный экран использует русский шрифт Roboto. Элементы управления создаются
из возможностей API: включение/выключение, пауза, яркость и другие диапазоны,
режимы, RGB/HSV-палитра с цветными образцами, температура белого света и световые сцены.
Ползунок отправляет значение после отпускания пальца; дробный шаг сохраняется.
Для диапазонов без произвольного выбора значения доступны относительные команды.
Неизвестное состояние отмечается явно. Кнопка «Обновить» запрашивает состояния вручную.

Команды отправляются через POST /v1.0/devices/actions в фоновой задаче.
На время запроса повторные нажатия блокируются; проверяется результат DONE/ERROR
для конкретного устройства и умения, затем состояния запрашиваются заново.
Автоматического повтора команд нет: при обрыве ответа действие уже могло выполниться.
Ошибки сети после первой загрузки оставляют карточки на экране и показываются в строке статуса.
При HTTP 403 проверьте право iot:control и при необходимости получите новый токен.
Колонки Алиса, для которых Яндекс API не возвращает умений, показываются
с пояснением об отсутствии доступного управления.

## Конструктор плана на экране

Откройте **План** в постоянной верхней навигации.
Это 2D-редактор одного этажа с прямоугольными комнатами на сетке 0.5 м.
Поле первой версии — 20×15 м; доступны до 24 комнат, 64 устройств и 64 проёмов.

1. Выберите **+ Комната** и потяните по свободной сетке. Минимум — 1.5×1.5 м.
2. В режиме **Выбор** перетаскивайте комнату. Размер меняется за правый нижний
   угол или кнопками ширины/длины справа. Пересечения комнат запрещены.
3. **Название** открывает сенсорную русскую клавиатуру и готовые названия комнат.
4. Выберите **Дверь** или **Окно** и коснитесь нужной стены.
5. Нажмите **Устройство**, выберите его из списка справа и коснитесь места
   в комнате. Затем задайте **Снизу / Центр / Сверху**. В режиме **Выбор**
   значки перетаскиваются, включая перенос в другую комнату.
6. **Обзор** перемещает вид, **- / +** меняют масштаб, **Весь план** вписывает комнаты.
7. **Отменить** возвращает последние 20 действий. **Удалить** убирает выбранный
   объект с плана; удаление комнаты снимает размещение её устройств и проёмов.
8. Нажмите **Сохранить**, чтобы записать план в NVS. Переключение раздела оставляет
   несохранённые изменения в оперативной памяти до перезапуска.

Планировка хранится отдельно от подключений в JSON версии 1. Координаты
устройств привязаны к комнате, поэтому сохраняются при её перемещении и изменении
размера. Импортируются только устройства, которые уже доступны через подключённые источники;
редактирование плана не отправляет команд технике и не меняет комнаты в Яндексе.
Обычная прошивка приложения сохраняет NVS; полное стирание flash удалит план.
При ошибке записи индикатор изменений остаётся активным, а ошибка видна на экране.
Браузерный редактор сможет использовать ту же модель планировки.

## Объёмный вид дома

Кнопка **Дом** в постоянной навигации открывает объёмный вид сохранённой/текущей
планировки. Обратный переход — **План**. Несохранённые изменения конструктора
также видны в доме.

- Полы, стены, двери и окна строятся из той же модели. Общие и частично общие
  границы соседних комнат не рисуются дважды.
- Стены полупрозрачные: кнопка **Стены** переключает 27%, 43% и скрытие стен.
  Двери и окна показаны как проёмы с рамами.
- Уровень устройства задаёт высоту над его точкой на полу: снизу, середина,
  сверху. Цветная метка и линия к полу показывают высоту. Высота стен для
  отображения — 2.8 м; отметки устройств используются как условные уровни.
- Нажатие значка открывает существующую панель управления устройством.
  Если значки перекрываются, появляется выбор устройств. Недоступное в текущем
  списке Яндекса устройство остаётся на плане, но команды ему не отправляются.
- **Все уровни / Снизу / Середина / Сверху** фильтруют значки; **Поворот**
  меняет ракурс на четверть оборота. Дом автоматически вписывается в экран.
  Перетаскивание и ручное масштабирование в объёмном виде отключены.
- Включённое освещение подсвечивает пол соответствующей комнаты.

Это изометрическое отображение без крыши, рассчитанное средствами LVGL.
Проекция, высота и области нажатия используют одни координаты. Повороты,
прозрачность и фильтры не меняют сам план и не отправляют команды устройствам.

## Плавность интерфейса

Для ESP32-P4 задан интервал обновления LVGL 16 мс вместо 33 мс,
два программных потока отрисовки через FreeRTOS, кэш стилей и функции
строк стандартной библиотеки. Компиляция использует оптимизацию скорости
`-O2` вместо отладочной `-Og`. Частоты CPU и PSRAM не повышаются.
Эти настройки относятся и к прокрутке списка, и к конструктору/виду дома.
16 мс — интервал планирования, фактический FPS зависит от нагрузки сцены.

Вид дома кэширует команды рисования без повторной сортировки стен,
разбивки проёмов и измерения текста при обычной перерисовке.
Поворот, фильтры, прозрачность, выбор и обновление устройств
перестраивают кэш; полупрозрачные стены сохраняются.

Для замера на панели включите **menuconfig → Home Panel → Log display FPS
every 5 seconds**, соберите и прошейте. Во время непрерывной прокрутки в мониторе появится `UiManager: Display FPS: ...`.
На неподвижном экране низкие значения нормальны: LVGL перерисовывает изменения.
Параметры заданы в `sdkconfig.defaults.esp32p4`; текущий локальный `sdkconfig`
тоже обновлён. При использовании другого старого sdkconfig проверьте эти
параметры отдельно, так как defaults не заменяют сохранённые значения.

Рекомендации по настройке:
[Espressif esp_lvgl_adapter](https://docs.espressif.com/projects/esp-iot-solution/en/latest/display/tools/esp_lvgl_adapter.html).

## Структура

- main/src/main.cpp — запуск Ethernet, контроль подключения, цикл синхронизации.
- HttpsClient — HTTPS, авторизация и ограничение ответа до 32 KiB.
  Возвращаемое тело принадлежит клиенту и действительно до следующего send или удаления клиента.
- DeviceManager — проверка JSON и атомарная замена списка под mutex.
- DeviceAction — проверка команд по возможностям устройства, JSON и разбор результата.
- UiManager — очередь простых сообщений и работа с LVGL под блокировкой BSP.
- HomePage / LoadingPage — список и состояния загрузки/ошибок.
- FloorPlan / FloorPlanEditor — модель плана, проверка геометрии, история отмены
  и сенсорный конструктор. PlanStorage сохраняет документ в NVS.
- HouseProjection / HouseView — проекция, общие стены, проёмы, прозрачный дом
  и выбор устройств на разных уровнях.

Буферами дисплея управляет BSP; приложение не подменяет их после инициализации.
Для ESP-IDF 6.1 compat/idf61 адаптирует старый интерфейс копирования кадров
esp_lvgl_adapter 0.1.x к публичному esp_async_color_convert. DMA2D и завершение
операции в прерывании сохраняются; файлы managed_components не изменяются.
Корневой CMake также задаёт зависимости драйверов BSP и совместимое имя
поля RGB-порядка для HX8394 на SDK 6.x.
compat/idf61/bsp_ek79007.h сохраняет штатные тайминги панели 1024×600,
задаёт входной и выходной цветовые форматы новым DPI API и включает DMA2D
через esp_lcd_dpi_panel_enable_dma2d вместо удалённого флага use_dma2d.

## Проверки

tests содержит независимые тесты DeviceManager на компьютере с настоящим cJSON
и подменой mutex FreeRTOS. Проверяются ошибочные ответы, сохранение списка,
повторный успешный запрос, дубликаты ID, тайм-аут и нехватка памяти для mutex.
Тесты HttpsClient проверяют первый и повторный GET без Content-Type,
переход POST → GET, сброс авторизации, ошибки подготовки и переполнение ответа.
Сеть в этих тестах имитируется; реальный токен не нужен.
Тест HomeAssistant проверяет разбор сущностей, ограничения команд, URL и токена,
а также независимую замену и очистку списков источников. UI-тест проверяет
совместный список, сохранение HA при выходе из Яндекса и обратный случай,
блокировку незавершённой команды другого источника, выбор устройства на проекции,
форму настройки, маскировку/очистку токена и положение экранной клавиатуры.
Снимки: `connections.ppm`, `connections-both.ppm`, `home-assistant-settings.ppm`.
Соединение с реальным сервером HA и сохранение его настроек в NVS проверяются на плате.
Тест YandexAuth проверяет Device Flow, интервал и замедление опроса, отмену,
истечение кода, отказ в доступе, права токена, восстановление/обновление сессии,
ошибки сохранения и выход с отзывом токена. UI-тест открывает раздел Яндекса,
проверяет QR, временный код, отмену и выход; снимок — `yandex-login.ppm`.
Настоящая запись токенов во flash и полный вход с подтверждением на телефоне
проверяются на панели после прошивки.
Проверяются также разбор умений, диапазонов и комнат, границы значений,
относительные команды, допустимые режимы и ошибки действий внутри HTTP 200.
При IDF_PATH, указывающем на SDK 6.1, также проверяется преобразование
координат, форматов RGB565/RGB888 и передача callback в слое совместимости DMA.

В терминале с компилятором C/C++ и CMake:

```powershell
cmake -S tests -B tests/build
cmake --build tests/build --config Debug
ctest --test-dir tests/build -C Debug --output-on-failure
```

Для проверки настоящих виджетов LVGL без платы добавьте при конфигурации
`-DHOME_PANEL_UI_TESTS=ON`. Тест проверяет нажатия, защиту от повторных команд,
отправку ползунка после отпускания, выбор цвета, отказ очереди и обновление
экрана. Снимок интерфейса сохраняется в каталоге сборки как home-page.ppm.
Тест модели FloorPlan проверяет геометрию, историю, связи объектов, сохранение
и атомарный отказ на некорректном JSON. UI-тест рисует комнату через настоящую
обработку указателя LVGL, проверяет клавиатуру, перенос и размер комнат,
проёмы, размещение устройств, высоту и повторное открытие сохранённого плана.
Снимки конструктора и клавиатуры: floor-plan-editor.ppm и floor-plan-keyboard.ppm.
В тестах NVS заменён хранилищем в памяти; запись во flash требует проверки на плате.
Объёмный вид проверяется на четырёх ракурсах: высота значков на одинаковых XY,
границы кадра, отсутствие двойных общих стен, проёмы, фильтры, перекрытия,
неподвижность камеры при свайпах и управление из дома. Снимки: house-perspective.ppm,
house-rotated.ppm и house-levels.ppm. Для локализованного MSVC зависимости
от заголовков проекта заданы явно, чтобы не использовать устаревший ABI классов.

pytest_home_panel.py — отдельная аппаратная проверка размера home_panel.bin
и запуска UI через pytest-embedded-idf. Для неё нужна подключённая плата.

После прошивки проверьте: загрузку списка; извлечение и возврат Ethernet-кабеля;
запуск без DHCP; ошибочный токен; обновление списка через минуту.
